一、唯一呈递入口（代码复用点与删掉的重复逻辑）
----------------------------------------------------------------------------
复用点：core/prompt_builder.py:_render_chat_line(row, *, content, name_resolver,
identity_ctx, with_speaker, bot_prefix, media) 是模型可见聊天行的唯一构造函数。
  · render_current_rows        → _render_chat_line(..., media="summary")
  · _render_recent_messages_block → _render_chat_line(..., bot_prefix=True)
  · _render_steer_message_line → 来源闸后调用 _render_chat_line(..., media="steer")
删掉的重复逻辑（三份各自拼前缀）：
  1) _render_message_line 里的 prefix/identity_prefix/at_mark/speaker/媒体尾缀整段；
  2) _render_steer_message_line 里的 at_mark/identity_prefix/tag/mid/body 拼接与
     media 标签、`.strip()/.rstrip()`；
  3) _render_recent_messages_block 循环内的 bot_prefix + speaker_tag + identity +
     m:id + 媒体清单逐行拼装。
收敛的判据：speaker 省略只由 _private_single_human(rows, is_private) 决定，
current 与 steer 共用（此前 steer 无此概念，私聊单人行照常带 [id=…]）。

五、非呈递语义不变（逐项核对）
----------------------------------------------------------------------------
· 注入时机/防抖/direct-followup 路由/运行控制/回执/台账：未改；relay 只是把既有
  is_private 传给 render_steer_rows。
· seen：_steer_seen_mark/_steer_seen_filter 未改；渲染去重仍按 source_row.id。
· 台账：steer_ledger 仍存 rendered_line（格式随呈现改变，sender/m_id/幂等判据不变）。
· 对账命中：判据从「content 含 [m:id]:」改为 _steer_line_hit_pattern(m_id)
  （行首该 m:id，强提醒/身份栏/旧 [id=…] [m:id]: 可前置）。语义仍是「这条原始消息
  的聊天行是否真的出现在模型可见转录里」；`[m:id]:` 形态本身仍命中（前缀不含要求
  紧跟冒号），旧台账已送达行照样核销，不会重复补投。
· 回收剥壳：strip_steer_presentation 认新文法（群/私、有无冒号）并继续剥旧文法，
  幂等（不叠壳）；仍要求至少一个机器锚点，`[主人] 你好` 这类可能是用户原文的行
  不剥——不吞正文。
· 原文回投/作者还原：_pending_steer_recovery_rows 仍按台账 rendered_line 子串匹配，
  改用新格式后 pending 与台账两边同源，行序与作者还原回归全过。
· 系统提示词：一字未改（本项不动提示词正文；decision_protocol 里
  「steer 注入，以 [id=…] 行出现」这句在私聊单人 steer 已无 [id=…] 行，
  按「不代写提示词正文」保留未改，交主会话定夺）。

七、保留差异与已知限制
----------------------------------------------------------------------------
1) steer 媒体形态仍是完整寻址标签 [图 m:id#idx] + 随条读图提示；current/recent 是
   紧凑清单 (图#0)。这是 steer 走文本通道、媒体不内联的真实差异，按参数保留。
2) 历史行对自己发出的 bot 行多 [bot]（recent 与 current 的真实差异，按参数保留）。
3) 私聊单人行省略 speaker 的判据是「私聊 + 该批只有这一行 + 真人」：私聊一次 steer
   多行时与 current 多人批一致地带 speaker（同一判据、同一输入→同一输出）。
4) 私聊无 m:id 且无强提醒的 steer 行（[主人] 正文）在回收剥壳时保留身份栏：没有
   机器锚点就无法与用户正文区分，按「不吞正文」处理；这类行极少（需同时满足无
   插件号 + 被上游吞 + 私聊单人）。不伪造 m:id。
5) prompt_dump 的真实群聊/私聊样本须部署后由主会话取主实例实测；本卡未部署、
   未重启、未采样，只用离线 smoke 验证字段齐全（system + messages/input +
   interface + sha/time，内联图片按长度占位）。
6) NoneBot 无 adapter 的 RuntimeWarning 与既有 ResourceWarning 不影响测试通过。
